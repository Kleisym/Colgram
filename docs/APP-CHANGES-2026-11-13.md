# Меню, источники и расход ресурсов

## Настройки

- Сетевая секция снова получает реальные позиции строк вместо `-1`.
- Подписка использует `TextSettingsCell` и участвует в обработке нажатий.
- «Обычный интернет» выключает WARP, прокси, автоматическое подключение,
  локальный DPI-маршрут и подбор адреса DC. Прокси остаются в сохранённом каталоге.
- «Экономия трафика и автозагрузка» открывает штатный экран Telegram;
  «Кэш: размер и срок хранения» — штатный экран управления кэшем.
- На экране настроек состояние сети обновляется раз в 1,5 секунды только
  при видимом экране и изменившемся состоянии. После ухода таймер снимается.
- Долгое нажатие на WARP открывает параметры релея сразу, без предварительного тапа.

## Переключение WARP

- Регистрация, запуск и остановка проходят через последовательный фоновый исполнитель.
- Каждый запуск получает поколение. Отмена делает его старые результаты недействительными.
- При выключении немедленно вызывается `cancelPendingStart()`, а тяжёлая очистка
  продолжает работу в фоне. Интерфейс не ждёт блокировку длительного запуска.
- Флаг настройки обозначает запрошенный режим и ставится только по нажатию.
  Завершившийся старый запрос не включает его повторно.
- Результат запроса VPN принимается только для актуального поколения.
- Подключённое состояние берётся из ядра, а не из положения переключателя.
- WARP и подписка используют один Android VPN-слот; перед новым туннелем
  предыдущий маршрут последовательно останавливается.

## Каталог прокси

Добавлены либо исправлены машиночитаемые TXT-источники:

- Thordata, ProxyScrape, IPLocate, Proxifly;
- TheSpeedX, HProxy, VPSLabCloud, OpenRay;
- Zaeem20, hideip.me, Jetkai, Monosans;
- API ProxyScrape, Hookzof, ShiftyTR и Proxyspace.

Исходные MTProto-фиды сохраняются. Полная проверка 24 предложенных страниц
находится в `proxy-source-audit.json`. HTML-каталоги, CSV, SOCKS4 и списки VLESS/
Shadowsocks не подаются парсеру SOCKS5. Подписки импортируются отдельным меню.

Правила обработки:

- SOCKS5 и HTTP — разные типы; чужой URI-префикс не меняет тип фида.
- Разбираются обычные `host:port`, корректные URI и IPv6 в квадратных скобках.
- Порты ограничены диапазоном 1–65535; частные/loopback-адреса из общих
  HTTP/SOCKS5-фидов отбрасываются без DNS-запроса.
- Только известный формат hideip.me получает адаптер колонки страны.
  Строки с полями аутентификации не принимаются как страна.
- Параметры сохраняемой идентичности нормализуются; повторные адреса одного
  типа не создают новые узлы.
- Сначала идут подтверждённые Telegram узлы, затем TCP-кандидаты, непроверенные,
  неудачные и карантинные. Нулевой RTT допустим, неизвестный RTT не равен нулю.
- Состояния для сортировки снимаются один раз: параллельный результат проверки
  не нарушает контракт компаратора. Равные RTT разрешаются адресом, портом,
  типом и секретом; тип и секрет не смешиваются при дедупликации.
- Сохраняются ограничения пула: 120 MTProto, 120 SOCKS5 и отдельные локальные слоты.
  Публичному экрану передаются максимум 30 кандидатов.
- На проход выбираются 3 MTProto-ссылочных, 2 JSON и 6 SOCKS5-фидов, а также
  по 2 HTTP/SOCKS5-релея. Окно источников сдвигается и сохраняется между запусками.
- Обновления не пересекаются и разделены минутным интервалом.
- Быстрые HTTP-загрузки ограничены 1 МиБ и десятисекундным бюджетом чтения
  плюс таймаут одного блокирующего чтения. Стандартный HTTP-клиент обрабатывает
  chunked-ответы и TLS вместо ручного чтения CONNECT-ответа в этом пути.
- Нативная проверка Telegram остаётся критерием рабочего прокси; TCP-connect
  сам по себе не превращает кандидата в подтверждённый маршрут.

## Расход ресурсов

- Убрано отложенное открытие баз Telegram из UI-потока: параметры закрытого
  соединения не ускоряли рабочие соединения Telegram.
- Необязательный стартовый сбор источников начинается после 15-секундного окна
  запуска и выполняется фоновым низкоприоритетным исполнителем.
- Сохранённое `auto_proxy_enabled=false` больше не перезаписывается миграцией.
- Экономия места управляется ограничением кэша, сроком хранения и автозагрузкой
  медиа. Повторная бесконечная компрессия не запускается: уже сжатые медиа и
  зашифрованный сетевой поток не становятся меньше от повторного сжатия.
- HTTP CONNECT и SOCKS5 сами по себе не являются шифрованием транспорта.
  TLS-проверка HTTPS сохраняется; данные Telegram защищает MTProto, а WARP
  предоставляет отдельный шифрованный туннель.

## Проверки

```powershell
python scripts/test_app_regressions.py
python scripts/host_verify.py --jvm-tests
python scripts/colgram-check.py --syntax --core --all-templates
```

`test_app_regressions.py` проверяет десять контрактов подключения к приложению.
`ColgramProxyPolicyTest` исполняет 56 JVM-проверок парсера, сортировки, поколений,
сдвига источников и ограниченного чтения. `ColgramSettingsRowsDeviceTest`
проверяет реальные позиции/типы строк и сохранение явного выключения в Android.
Шаблон инструментальных тестов добавлен в установщик патчей; его выполнение
требует подключённого Android-устройства.
