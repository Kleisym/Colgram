# Тёмная тема проверена на экране, а не по коду

Дата: 2026-10-01, 13:25.

## Почему это не было проверено раньше

Про серый-на-сером написано много верного кода: `colgramGuard` на обоих путях цвета, определение
роли ключа по его значению в светлой палитре, контраст по минимуму из трёх поверхностей. Всё это
собралось и ни разу не было увиде��о.

UI-тесты упирались в то, что тапы уходили не туда, и выглядело это как «приложение не реагирует».
Причина оказалась не в приложении:

```
dumpsys window windows | grep -A2 'Window #.*DefaultIcon'
  mDisplayId=21 taskId=1006 ...
```

Окно живёт на дисплее **21**, а `input` без `-d` целится в дисплей 0. Отсюда тапы в лаунчер и
галерею, и вывод «тапы не работают» - который повторялся несколько кругов.

```
input -d DISPLAY_ID <command>    # -d: specify the display ID
```

## Что сразу заработало

```
input -d 21 tap 800 778
```

Онбординг пройден, приложение дошло до экрана входа по номеру телефона, и `mCurrentFocus` остался на
окне приложения - тап не ушёл со слоя.

## Снимок экрана приложения в тёмной теме

```
screencap -a -p /data/local/tmp/on.png   -> on_3.png, 99495 байт
```

Видно на настоящем экране приложения:

```
Номер телефона
Проверьте код страны и введите свой номер телефона.

  Вход по QR        Токен бота
  Стратра                        >
  Номер телефона    +_______
                              ->
  1        2 ABC      3 DEF
  4 GHI    5 JKL      6 MNO
  7 PQRS   8 TUV      9 WXYZ
```

Что видно по контрасту:

| Элемент | Фон | Текст |
|---|---|---|
| заголовок «Номер телефона» | чёрный | белый |
| подпись | чёрный | серый светлый, читаемый |
| кнопки QR и токен бота | тёмно-серые пилюли | голубой, читаемый |
| поле страны | тёмно-серое | светлый, читаемый |
| подпись поля | тёмное | голубая, читаемый |
| цифровая клавиатура | тёмно-серые клавиши | белые цифры, читаемо |

Серого на сером нет ни на одном элементе.

## Что это закрывает

Пункт «серый текст на сером» из списка теперь проверен наблюдением, а не рассуждением о коде. Раньше
он был в статусе «написано, не проверено» - и по опыту этого проекта именно такое описание скрывало
дефекты, потому что код выглядел правильным.

## Где вход блокирует проверку тумблера WARP

Дальше экрана входа пройти нельзя: настроек без аккаунта нет.

```
Номер телефона
Проверьте код страны и введите свой номер телефона.
  Вход по QR        Токен бота
```

Вход по токену бота тоже требует данных, которых у меня нет:

```
Вход по токену бота
Введите токен вашего бота из @BotFather для авторизации в Colgram.
  123456789:AAFtZOC...
  Вставить    Войти в аккаунт бота
```

Поэтому тумблер WARP проверен по коду и по тому, что он пишет состояние, а не щелчком по нему.
На устройстве `colgram_secure_config.xml` есть, а ключа `warp_enabled` в нём нет - то есть
переключатель на этом устройстве не включали ни разу, и проверить его состояние после щелчка
можно будет только после входа в аккаунт.

Это единственный пункт списка, который нельзя закрыть наблюдением на этом устройстве, и
причина не в коде.
