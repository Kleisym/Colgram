# Что в этом проекте выглядело готовым и не было готовым

Дата: 2026-10-01.

Пять случаев, где код был написан, документация подробная, компиляция зелёная — а работа не
происходила. Ни один не был виден ни в сборке, ни в логе. Общая черта: **проверялось наличие кода,
а не то, вызывается ли он и с чем.**

| Что | На вид | На самом деле |
|---|---|---|
| Отчёт о крашах | класс, нативная библиотека, документация | `install()` не вызывался нигде |
| Автоответчик | тумблер, конфиг, вызов `sendMessage` | искалась перегрузка `(CharSequence, long)`, которой нет; не отправил ни одного сообщения |
| Правка сообщений | `getMessage(...)` на `MessagesController` | метода `getMessage` там нет вообще |
| Счётчики вкладок поиска | `getItemTitle` с числом | заголовки не перерисовывались при вводе; числа показывали прошлый запрос |
| Библиотека MASQUE в APK | `.so` на месте | на месяц старше исходника, без поддержки обхода |

## Общий механизм у четырёх из пяти

**Молчаливое продолжение.** `getMethod` возвращает `null`, и код идёт дальше как ни в чём не бывало.
Исключения нет — есть условие, которое не совпало. То же самое у неустановленного обработчика
крашей и у неперерисованных заголовков: всё выглядит включённым, потому что включение и есть
состояние флага.

Рассыпанное по трём слоям Java-кода, который компилируется без единой ошибки.

## Почему это переживало несколько кругов проверки

Проверка сводилась к «файл существует, метод есть, сборка зелёная». Ни одна из этих вещей не
задаёт вопроса «а что произойдёт, когда дойдёт до этой строки». А произойдёт:

- обработчик крашей не встанет;
- сообщение не отправится;
- править сообщения будет нечем;
- числа останутся от прошлого поиска;
- обход не задействуется, и туннель упадёт по таймауту.

Последнее выглядит как проблема сети, и ею и объяснялось несколько кругов подряд.

## Что добавлено против этого

```
python scripts/run_all_checks.py

 [ok] reflection in colgram-core  -  checked 103 lookups, 47 not statically resolvable, 0 unresolved
 [ok] reflection in the UI files  -  TMessagesProj/colgram: checked 6, skipped 12, unresolved 0
 [ok] auto-reply send path  -  [ok] auto-reply send path resolves: SendMessagesHelper$SendMessageParams.of(String, long)
 [ok] packaged masque library  -  3 abis current, 0 stale, 0 missing
 [ok] brand strings  -  total changed=0  remaining=354

all checks passed
```

Каждый из них проверен в обе стороны: сломанный вариант даёт ненулевой код выхода, исправленный —
нулевой. Проверка без такой проверки не годится: она тоже может быть написана и никогда не
срабатывать.

## Чего проверки не делают

Типы параметров в рефлексии не сверяются: нужна настоящая проверка типов. Подмена
`"current", Context.class` на `"current", String.class` проходит незамеченной - имя и число
параметров совпадают, отличается только тип. Этот предел записан в
`reflection-sweep-found-broken-edit.md`, чтобы его не приняли за надёжность.

И ни одна проверка не запускает приложение. Единственное, что доказывает работу на устройстве,
это замер на устройстве - остальное ловит класс ошибок, при которых замер показал бы сетевую
проблему вместо своей.
